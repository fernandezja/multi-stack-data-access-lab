# Jedi Data Access Lab

Code kata and PoC (proof of concept) for comparing data-access implementations across technologies and languages while exposing the same HTTP contract over one MariaDB database

Implementations:

- API 1: TypeScript, Express and Prisma.
- API 2: .NET 10 Minimal API, Entity Framework Core 9 and Pomelo.

The project is designed to add other languages, frameworks or data-access strategies without changing the shared database contract

## Architecture

```text
Browser
   │
   ├── Astro + Nginx :4321
   │       ├── TypeScript API :3001 ─┐
   │       └── .NET API :3002 ───────┤
   │                                 │
   └────────────────────────────── MariaDB :3307
                                     StarwarsAcademy
```

The published ports bind to `127.0.0.1`. Inside Docker, APIs connect to `mariadb`; browser requests use `localhost`.

## Requirements

- Docker Desktop or Docker Engine with Docker Compose.
- PowerShell or Bash.

Main versions:

- MariaDB 11.4.
- Node.js 22.
- Prisma 6.16.2.
- .NET 10 with EF Core 9.0.9 and Pomelo 9.0.0.
- Astro 5.13.5.

_NOTE: EF Core 9 is used because it is the selected stable version compatible with the MariaDB Pomelo provider; the application runtime remains .NET 10_

## HTTP operations

Both APIs expose the same routes:

```http
GET /jedi
GET /jedi/{jediId}
POST /jedi
POST /jedi/search
GET /health
```

Create a Jedi:

```json
{
  "name": "Cal Kestis",
  "jediTypeId": 2
}
```

Search and paginate:

```json
{
  "searchTerm": "Skywalker",
  "pageIndex": 0,
  "pageSize": 5
}
```

`pageIndex` starts at zero. `pageSize` accepts values from 1 to 100. Search performs a count and executes `Jedi_Search`, which applies literal filtering, stable ordering by `JediId` and pagination.

## OpenAPI and Scalar

The .NET OpenAPI document is generated by `Microsoft.AspNetCore.OpenApi`.

The TypeScript OpenAPI document is generated during the build with `tsoa` from decorated controllers and models. The generated file is `api-ts/dist/swagger.json` and is served at `/openapi/v1.json`. Scalar consumes that endpoint at `/scalar`.

To generate it locally:

```powershell
Set-Location api-ts
npm install
npm run build
```

## Database and volume

MariaDB uses the named volume `mariadb-data`. Initialization scripts run only when the volume is empty.

If the database schema must be recreated, the following command is destructive because it removes the volume and all stored data:

```powershell
docker compose down -v
docker compose up --build -d
```

Do not use `down -v` when existing data must be preserved.

## Security and design notes

- `.env` contains local credentials and must not be committed.
- APIs use an application MariaDB user instead of `root`.
- The application user receives `SELECT`, `INSERT` and `EXECUTE`, but no DDL permissions.
- User input is parameterized and is not concatenated into SQL.
- CORS is enabled for local development.
- The stored procedure uses `LOCATE`, so `%` and `_` are treated as literal text.

The Astro interface currently supports provider switching, list retrieval and links to Scalar/OpenAPI. Search, inserts and invalid-input cases can be tested directly through Scalar
